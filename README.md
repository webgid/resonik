# RESONIK · новий сайт

Гілка `feat/resonik-figma-redesign`. Новий напрям — металеві вироби на замовлення. Стару Vite-програму з авторизацією, кошиком і попереднім асортиментом замінено. Попередня версія збережена в історії Git / `main`.

## Запуск

Node.js 20.9+ (рекомендовано 22+).

```sh
npm install
npm run dev -- --port 3230
npm test
npm run build
```

## Структура

- `src/app` — сторінки App Router, metadata, sitemap.
- `src/components` — окремі компоненти з сусідніми CSS Modules.
- `src/data/products.json` — товари, ціни, розміри, моделі авто, матеріали, кольори.
- `src/data/site.js` — навігація й кроки замовлення.
- `public/images/products` — прозорі PNG виробів.
- `public/images/backgrounds` — незалежні студійні фони.
- `public/design` — локальні оригінальні ресурси макета Figma.

Стиль: JavaScript / JSX, функціональні компоненти, модульні стилі, дані окремо від розмітки. Без Tailwind, Redux та старої авторизації.

## Як замінити виріб

Додайте прозорий PNG до `public/images/products`, змініть `image`, `imageAlt` та дані товару в JSON. Фон задається окремим полем `background`. Компонент `ProductMedia` накладає виріб на незалежний фон. Розміри карток фіксуються через співвідношення сторін, тому заміна фото не змінює сітку.

Щоб додати товар, додайте об’єкт з унікальними `id` та `slug` у `products`. Каталог, посилання, сторінка товару й sitemap створюються з цих даних.

Ціна $1000, габарити 2000 × 400 × 400 мм — попередні значення від замовника. Вага не вказана й показується як «Уточнюється». Сумісність, відтінок і фінальна ціна узгоджуються перед виробництвом. Вибір кольору не підмінює фото неіснуючим варіантом.

## Заявки

За вказівкою замовника працює тільки локальний перегляд. Форма перевіряє ім’я, номер до 12 цифр, згоду й показує підсумок. Дані нікуди не відправляються; зовнішніх запитів або імітації успішної відправки немає. Для запуску приймання заявок слід окремо підключити погоджений канал і серверну валідацію.

Сайт не опублікований. Перед публікацією перевірте домен `resonik.com`, реальні фотографії, характеристики та канал заявок. Концептуальні візуалізації підписані; вигаданих відгуків чи кейсів немає.

## Перевірка реалізації

- Production build і тести пройдено.
- Перевірено головну, каталог і обидва товари на 390 / 768 / 1440 px; додатково переповнення на 320 / 1024 px.
- Перевірено меню, Escape, перехід меню → форма, передавання комплектації та обмеження номера.
- У браузері немає помилок JavaScript і зламаних зображень; невідомий маршрут повертає HTTP 404.
- Зображення оптимізуються Next Image; шрифти локальні з ліцензіями.

## Сторінки бренду

Головна — огляд бренду й виробів з короткими переходами. Повний опис виробництва винесено на `/production`, процес замовлення — на `/how-to-order`. Каталог і кожен товар також мають власні адреси. Посилання в шапці, меню та футері ведуть на сторінки, а не на якорі головної.

Спільна шапка залишається зверху під час прокручування на всіх розмірах екрана. Перевірено її положення після скролу, окремі H1, навігацію комп’ютера й телефону та sitemap.
